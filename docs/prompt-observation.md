# Local agent prompt observation

Temote MCP keeps direct agent prompt observations in an owner-only local store.
This is an optional observation path. It never starts a task, changes task
execution, or exposes raw prompt bodies through ordinary MCP, HTTP, or Fabric
context. The stored envelope is version 1 and accepts only
`user_prompt_accepted`, `user_steer_accepted`, `conversation_bound`,
`conversation_unbound`, and `prompt_observation_gap`. The accepted user kinds
require a bounded local body (at most 64 KiB); the other kinds reject one.
Gap records require a typed reason code.

## Current capability assessment (2026-10-06)

| Surface | Native capability | Runtime coverage | Reason |
| --- | --- | --- | --- |
| Codex 0.157.1 direct UI | partial | unavailable | The documented `UserPromptSubmit` command hook sees a user prompt and turn ID before submission, but is not an accepted-turn receipt. No trusted hook adapter is installed by Temote. |
| Temote-owned Codex app-server | supported | supported | The v2 `item/started` `userMessage` adapter records accepted single-text items from conversations owned by this app-server client. Other user content produces a typed gap. This does not cover unrelated direct UI conversations. |
| OpenCode direct UI | unavailable | unavailable | No installed authenticated accepted-user-turn adapter for unrelated direct conversations has been verified. |
| Devin ACP 3000.11.1 direct UI | unavailable | unavailable | The installed `devin acp` surface is a client-driven session/prompt server. No verified hook for unrelated direct turns was found. |
| Devin Cloud direct UI | unavailable | unavailable | No installed stable direct user-message webhook was verified. |

The Codex schema was generated read-only using `codex app-server
generate-json-schema`; the [Codex hooks reference](https://learn.chatgpt.com/docs/hooks)
documents `UserPromptSubmit` and its pre-submit `prompt` / `turn_id` fields.
These capability labels describe the surfaces examined, not live acceptance.
Recheck them when installed versions change. Never synthesize accepted prompts
from Temote task metadata or from timing.

The owned adapter handles the version 2 `item/started` notification shape
generated by Codex 0.157.1: `threadId`, `turnId`, `startedAtMs`, and an item
with `type: "userMessage"`, a stable `id`, and `content`. It treats the
emitted user-message item as the acceptance observation. Only one nonempty
bounded `text` input becomes `user_prompt_accepted`; mixed, non-text, empty,
or oversized content creates `prompt_observation_gap` with
`unsupported_content`, without copying a partial instruction. Other item
types, including `hookPrompt`, and pre-submit hooks are excluded. The source
event ID is the Codex item ID, so replay uses the ingress store's existing
identity and conflict checks.

## Ingress and correlation

`temote-mcp observation prompt-listen` serves a private Unix socket at the
owner state directory's `agent-prompts/ingress.sock`. It is disabled until
the local owner runs this command.
Each connection sends a four-byte big-endian length followed by one JSON
request `{schema_version: 1, envelope, body}` capped at 68 KiB and receives
one length-framed bounded structural receipt. The socket checks OS peer
credentials and never accepts a caller-supplied UID. A session-bound envelope is
accepted only while its full `session_id` / `started_at` / `process_id` /
canonical scope fence
matches the active managed session. The structural source identity
`host + agent + conversation + source_event` is replay-safe: a repeated body
and envelope returns the same observation ID, while a conflicting replay
fails closed. A source without a stable event ID must persist one before
retrying delivery. Observer errors are best effort for the coding task.

For a Temote-owned Codex task, the adapter reads the retained task after an
exact thread and turn match, retries briefly if a notification precedes the
turn-start response, and records the canonical `execution.id` derived from
the task ID and generation. The native Codex `turnId` remains the separate
`agent_turn_id`. It checks the task's owner and canonical scope, then the
ingress rechecks the live full session-instance fence before writing. A
delivery or observer error never changes the delegated task outcome.

Raw content is a separate 0600 file under the owner-only state directory.
The bounded record stores only its local opaque reference, length, and digest.
No generic raw prompt read tool exists. Context projection carries at most 16
structural prompt references, eight steers and eight conversation identities.
It reports capability coverage, last observed time, degradation, and exact
session instance. Conversation coverage includes the latest source event ID
and any typed gap reason. It does not claim a text summary when only a digest exists.
Provider-neutral worker input may use these structural fields; raw body export
requires a separate explicit policy and is not enabled here. The deterministic
worker projection permits at most 16 fresh structural user-instruction refs
within 24 hours, and the normal context bundle uses an eight-ref subset.

`temote-mcp observation prompt-link <SESSION_ID> --prompt-id <UUID> --task-id
<UUID>` performs additive late correlation. It obtains the retained Codex
task through the typed read path, then uses its canonical `thread_id`, task
ID and established `execution.id`. The Codex `turn_id` is kept separately as
`agent_turn_id`; it is never substituted for Temote's execution ID. A current
host and full session-instance fence and matching source conversation are
required. The link is immutable and the context resolver distinguishes it
from unbound or merely explicit source IDs. Repository proximity and
timestamps cannot create an exact correlation.

No unrelated direct prompt hook was installed or activated in this workstream.
The owned app-server producer writes to the same private store directly; the
listener accepts owner-authenticated, source-asserted versioned local producer packets. These
commands are Unix-only owner CLI commands and are absent from stdio MCP,
public HTTP, and the gateway. External direct hook coverage remains NOT RUN.
